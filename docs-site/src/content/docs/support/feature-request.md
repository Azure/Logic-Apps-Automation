Feature requests are welcome — especially ones with a clear user story.

## File the request

→ [**Open a new feature request on GitHub**](https://github.com/serverless-paas-balam/project-otto/issues/new?template=feature_request.yml)

The link opens the feature-request form with labels and the priority dropdown pre-filled — you just describe the problem and the proposed experience.

:::note[Private preview]
The tracker is in a private repo today. If the link 404s, you don't yet have access — ping the team to be added.
:::

## What to include

A great feature request answers four questions:

1. **What problem are you trying to solve?** The "why," in user terms.
2. **What's your current workaround?** (If any.)
3. **What would the ideal experience look like?** A sketch, mock, or short example is great.
4. **Who else would benefit?** Single team, broad audience, or a specific role.

## Tips

- One request per issue, please — it keeps discussion focused.
- If you can show the request as a runnable example (a snippet of workflow JSON, a portal screenshot, an assistant prompt), do it.

## Voting

Add a 👍 reaction to existing requests you'd like to see prioritised. We use reactions and substantive comments as a signal.
