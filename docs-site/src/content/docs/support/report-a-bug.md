Bugs are tracked on **GitHub Issues**. The fastest path to a fix is a small, reproducible report.

## File the issue

→ [**Open a new bug report on GitHub**](https://github.com/serverless-paas-balam/project-otto/issues/new?template=bug_report.yml)

The link opens the bug-report form with labels and the severity dropdown pre-filled — you fill in description, steps to reproduce, and any logs.

:::note[Private preview]
The tracker is in a private repo today. If the link 404s, you don't yet have access — ping the team to be added.
:::

## What to include

A great bug report has five pieces:

1. **What you did** — the steps to reproduce, ideally with a workflow name, a run ID, or a screenshot.
2. **What you expected** — what should have happened.
3. **What actually happened** — the error message, broken output, or unexpected behaviour.
4. **Where you hit it** — workspace and project name, browser, approximate time.
5. **Anything else useful** — console errors, network responses, screenshots, or short screen recordings.

## Security issues

If you've found a **security vulnerability**, please **do not** open a public issue. Email the maintainers privately or follow the process described in [`SECURITY.md`](https://github.com/serverless-paas-balam/project-otto/blob/main/SECURITY.md) if present.

## Before filing

Search [existing issues](https://github.com/serverless-paas-balam/project-otto/issues?q=is%3Aissue) first — your report may already be tracked. If it is, add a comment with anything new you've learned (logs, a smaller repro, a workaround).

## Just have a question?

Use **[Request a feature](/support/feature-request/)** for product suggestions. For implementation questions or open-ended discussions, reach out via the team's preferred chat channel — links live in the private repo's README.
